# C03：完整 PD A/B 实测结果

日期：2026-10-10。A 为 C02 on、原生 LI 双写；B 为 C02 on、融合 LI 双写。
负载保持 131072 输入 / 1024 输出、64 请求、客户端并发 16，独立 D cache salt。
P PP2/TP16；D DP2/TP16/EP32；MTP5 eager，target FULL_DECODE_ONLY。
正式阶段不执行其他算子测试、microbenchmark 或 profiler。开发轮 A0/A1 不参与主比较。

## 判断与当前状态

两轮 B 的全请求 server/client ITL p50/p75/p90/p99 均低于两轮 A。四组两两比较中，全请求 server ITL p50 下降 0.64%～0.81%，server p99 下降 1.48%～4.58%，client p99 下降 0.66%～0.81%；正式输出吞吐提高 2.34%～3.44%。这些是实测轮次之间的算术变化，不是置信区间或收益保证。

**饱和子集 server ITL p99 和 TPOT 未一致改善。** 例如 A2→B1 的饱和 server p99 为 81.657→84.314 ms，增加 3.25%；A3→B1 则降低。A2/A3 的饱和请求数也从 13 到 32，不能以数千个相关 ITL 事件冒充大量独立重复实验。MTP 总接受率 A 为 59.14% / 57.39%，B 为 58.40% / 58.98%，没有一致提升。

当前保持 C03 **仅在实验实例开启**，用于后续 profiling 定位；通用配置缺省仍关闭。已经观察到全请求 ITL 改善，尚不能宣称饱和 server p99、TPOT 或 MTP 接受率普遍改善。profiling 数据独立于本表，不用于替换任何正式轮次。

## 口径与局限

- server TPOT = (末次−首次正token engine timestamp)/(1024−1)，由真实记录派生，非内置TPOT metric。
- client TPOT沿用现有压测：(SSE完成−首次可见输出)/(1024−1)。
- server ITL直接使用vLLM原metric对应事件间隔；client ITL为非空输出SSE到达间隔。MTP burst不按token均摊。
- 两台D的ITL histogram增量count/sum均与正式请求原始事件校验一致；每请求均校验1024个生成token。
- 每阶段两轮，保留分轮结果；事件相关，不声称统计显著性。所有四组A/B变化百分比见完整JSON。
- A使用自10月1日运行的服务；B在10月10日重启并重新capture，先完成128k/1k功能probe。配置/源增量受控，但进程热态不完全等价；未做ABBA，不能完全排除重启状态和时段差异。
- 局部writer有严格byte oracle；完整PD提供功能、长度、事件与性能验证，没有固定batch完整logits质量对比。
